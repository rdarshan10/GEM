Agent memory

When one fact changes, what else is now wrong?

Memory for AI agents stores facts and updates them when they conflict. It rarely asks which other facts were worked out from the one that changed.

GEM · Governed Evolving Memory · figures replay recorded runs (Jev + gpt-oss-120b)

Suppose an assistant knows you live in Bangalore. From that it has worked out a 45-minute commute, an alarm at 6:30 to beat the traffic, and a coffee maker that starts at 6:45. Then you tell it you've moved to Mumbai.

4 linksseparate the move from the coffee maker. The two share no words, so a similarity search won't connect them.

Any memory system will update where you live. The question is what happens to the commute, the alarm and the coffee maker, which were never wrong on their own terms and are now all wrong together. GEM records which facts were derived from which, and when one changes it follows those links.

Most decisions are cheap

–Jev calls and LLM calls for the write in Fig. 1.

Each hop asks one batched question of Jev, a small model that answers with probabilities rather than text: is this fact unaffected, and if not, can its new value be worked out? A confident “unaffected” stops the cascade; a doubtful one goes to a large language model. So does any fact that needs rewriting rather than flagging.

That split is what keeps the cost close to that of ordinary memory. In the relocation run, the large model was called once, to rewrite the address. Jev made the other five decisions.

What ordinary memory leaves behind

–facts built on the old platform were still served as true by flat memory.

Run the same write through flat memory, which checks the new fact against similar facts and stops there. When a team moves its service off AWS Lambda, flat memory updates the platform, and it drops the 15-minute handler limit, which it recognises as Lambda's. The cold-start delay, the latency budget built around it and the export chunked to fit the old limit never mention Lambda, so nothing sends it back to them.

Using it

GEM runs as an MCP server for agents such as Claude Code, or as a Python library. Every save returns the facts it updated and the facts it made stale, and search keeps outdated matches separate.

pip install -e ".[mcp,embeddings,jev]"
claude mcp add gem -- python -m gem.mcp_server
